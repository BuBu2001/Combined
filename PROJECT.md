# repo-describer — генератор описаний репозиториев (без ИИ, без GUI)

Проект объединяет два исходных репозитория в единый headless-конвейер:
человек нажимает «Составить описание» — инструмент анализирует весь
репозиторий и выдаёт папку с Markdown-файлами с чёткими пояснениями.

---

## 1. Исходные репозитории

| Проект | Источник | Роль в конвейере |
|---|---|---|
| **Doxygen** | https://github.com/doxygen/doxygen | Подход к анализу: извлечение структуры кода (классы, функции, модули) и doxygen-комментариев (`/** ... */`, `///`) через AST-парсинг. В самом инструменте используются tree-sitter-экстракторы, воспроизводящие семантику doxygen (определения + привязанные комментарии), а также парсер XML-метаданных для файлов `.md`. |
| **TiddlyWiki5** | https://github.com/TiddlyWiki/TiddlyWiki5 | Движок представления: формат тиссов `.tid` и headless-CLI `tiddlywiki` (установлен в `/workspace/node_modules/tiddlywiki`). Описание генерируется как набор тиссов и рендерится TiddlyWiki в HTML, который затем конвертируется в чистый Markdown. GUI не используется — только режим `node tiddlywiki.js ... --render`. |

Оба репозитория склонированы в `/workspace`:
- `/workspace/doxygen` (клон `https://github.com/doxygen/doxygen`)
- `/workspace/TiddlyWiki5` (клон `https://github.com/TiddlyWiki/TiddlyWiki5`)

---

## 2. Что делает проект

`repo-describer` — это CLI-инструмент («кнопочка "Составить описание"»),
который без участия ИИ и без графического интерфейса:

1. сканирует произвольный репозиторий;
2. извлекает структуру исходников (AST через tree-sitter, doxygen-комментарии);
3. собирает метрики (языки по tokei-подобной статистике, зависимости из манифестов, документация);
4. формирует wiki-тиссы в формате TiddlyWiki5 (`.tid`);
5. прогоняет их через headless TiddlyWiki CLI → HTML → Markdown;
6. выдаёт готовую **папку с множеством `.md`-файлов**: обзор проекта, структура каталогов, модули, классы/функции, зависимости, статистика.

### Язык вывода
Определяется автоматически по системной локали (`LANG`/`LC_ALL`/`LANGUAGE`):
русский при `ru_RU.*`, иначе английский. Переопределение: `--lang ru|en|auto`.

### Уровни детализации (выбирает пользователь)
- `low` — общий обзор: что за проект, языки, структура верхнего уровня;
- `medium` — плюс пофайловые карточки модулей с ключевыми определениями;
- `high` — максимум: каждая функция/класс с сигнатурой и извлечённым комментарием, полное дерево, зависимости, перекрёстные ссылки между `.md` (по модели вики-ссылок TiddlyWiki).

## 3. Архитектура

```
/workspace/repo-describer
├── describe.py              # Точка входа CLI («Составить описание»)
├── describer/
│   ├── __init__.py
│   ├── i18n.py              # Локализация RU/EN, автоопределение по локали ОС
│   ├── extractors.py        # Слой doxygen: tree-sitter AST + doxygen-комментарии
│   │                        #   (python, js, ts, c, cpp, java, go, rust)
│   ├── analyzer.py          # Обход репозитория: метрики, дерево каталогов,
│   │                        #   манифесты зависимостей, README/доки, XML (.md doxygen)
│   └── generator.py         # Слой TiddlyWiki5: .tid-тиссы → headless render → .md
│                            #   (+ fallback на прямой Markdown, если TW недоступен)
├── tw-plugin/               # Минимальная конфигурация TW-«вики» (recipes) для рендера
└── (использует) /workspace/node_modules/tiddlywiki/tiddlywiki.js
```

### Конвейер данных

```
       репозиторий
            │
            ▼
 ┌─────────────────────┐   подход doxygen: AST + комментарии
 │ analyzer.py         │──► модель RepoModel (файлы, определения, метрики)
 │  └─ extractors.py   │
 └─────────────────────┘
            │
            ▼
 ┌─────────────────────┐   формат TiddlyWiki5: title/tags/body
 │ generator.py        │──► *.tid (тиссы)
 └─────────────────────┘
            │
            ▼
 ┌─────────────────────────────────────────────┐
 │ node tiddlywiki.js wiki --load tid --render │  headless, без GUI
 │ [!is[system]] output.html                   │
 └─────────────────────────────────────────────┘
            │  HTML
            ▼
   html→markdown рендер ──► папка out/*.md  (готовый результат)
```

### Ключевые решения
- **Единое целое, а не два инструмента**: данные извлекаются по методологии
  doxygen (структура + документирующие комментарии), а представление живёт
  в модели тиссов TiddlyWiki5 — один и тот же артефакт (`.tid`) является
  и промежуточным форматом, и единицей вики; `.md` — финальная форма выдачи.
- **Никакой графики**: ни Qt/webview/GUI-зависимостей; только CLI и файлы.
- **Отказоустойчивость**: если TiddlyWiki-рендер невозможен (нет node, таймаут,
  пустой вывод версии 5.4.1), включается fallback — прямая генерация Markdown
  из той же модели, пользователь всегда получает папку `.md`.
- **Локализация** всей терминологии и текстов отчётов (RU/EN) в одном словаре `i18n.py`.

## 4. Использование

```bash
# «Кнопочка "Составить описание"»:
python /workspace/repo-describer/describe.py /path/to/repo -o out_repo --level high

# уровни: low | medium | high ; язык: auto(по системе) | ru | en
python describe.py ./my-app -o docs_out --level medium --lang ru

# без TiddlyWiki-рендера (прямые .md):
python describe.py ./my-app --no-wiki

# сохранить промежуточные .tid рядом с .md:
python describe.py ./my-app --tid
```

Результат — папка вида:

```
out_repo/
├── 00-Обзор.md / Overview.md
├── 01-Структура.md / Structure.md
├── 02-Модули/… (по модулям)
├── 03-Зависимости.md
└── 04-Статистика.md
```

## 5. Зависимости окружения

- Python ≥ 3.12, пакеты: `tree-sitter`, `tree-sitter-language-pack`
- Node.js + `tiddlywiki` (npm, headless CLI) — слой представления TiddlyWiki5
- Статистика строк опирается на принципы подсчёта tokei (коды языков те же)
